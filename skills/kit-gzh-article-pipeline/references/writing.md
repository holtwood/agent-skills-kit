# 中文表达与作者声音

用于写初稿、深度改稿和中文审校。默认是个人开发者讲清楚自己的产品、实践与判断，技术准确，语气自然。用户明确风格、文章用途和本人样稿优先于默认。

## 作者声音

需要长期保持风格时，优先读取文章工作区 `author-voice.md`、项目既有写作配置，其次读取 `~/.config/agent-skills-kit/article-voice.md`。记录读者、语气、术语、样稿路径、喜欢和不喜欢的表达，无需每篇重新问。用户已经明确的偏好可以记录；样稿推断的习惯写为观察，不冒充作者明确要求。仓库不保存个人经历与账号信息。

从本人样稿观察句长、段落推进、观点强度、技术解释深度和收尾方式。借鉴表达方式，不移植样稿中的故事、数字、结论或口头禅。没有样稿就用平实默认，不声称已复刻作者声音。

第一人称只用于作者给出的经历与判断。缺少亲历仍可写好文章，用具体操作、真实例子和解释来支撑，不补写“凌晨三点”“折腾半天”“我当场愣住”等故事。借鉴其他博主时取其方法，不默认变成对方的语气或价值观。

风格北极星用平克《风格感觉》的古典风格：写作是带读者看作者已经看见的东西——文章是观看世界的一扇窗，呈现事实而非炫耀修辞；简洁但不简单。技术文章最大的病根是他说的「知识的诅咒」：作者默认读者知道自己知道的事，不肯解释术语、不肯补推导、不肯给细节。编辑时主动问：这段假定读者懂什么？该解释的解释，该给的细节给，该删的背景删。

立场也算风格资产。AI 默认产出四平八稳的共识——面面俱到的中立比不完美的真实判断更没人味。作者的偏好、取舍、自嘲和有棱角的判断要保留；拿不准时宁可标「推断」，不把犹豫磨成断言、也不把断言磨成没立场的和事佬。

同质化是比单篇质量更深的坑。Science Advances 2024 的因果实验（Hauser & Doshi）：拿到 AI 点子的作者写出的故事平均评分更高，但彼此更相似——个体获益、集体趋同，且后续研究（S294988212500091X）证明调参数、改提示词都弥合不了这个差距，只有人的输入多样性可以。这意味着「作者独有素材」（亲历细节、真实数字、个人立场）不是锦上添花，而是抗同质化的唯一有效变量——采访与口述环节因此不可省略；多篇连续产出时，刻意变换结构开头与收尾方式，别让六篇文章收敛到同一个模子。

两条写法和回收的硬经验：

- 风格规则要具体到可匹配才生效。对模型说「自然一点」「口语化」几乎无效——中文训练语料里翻译稿、论文、通稿占多数，抽象指令会被静默丢弃。规则要么写成「看见 X 换成 Y」的禁用/替换表，要么配一段 before/after 样例；形容词式的要求不构成约束。
- 改稿回收：交付后用户的手改是最高价值的风格信号，把「交付稿 vs 用户改后稿」的差异归纳进 voice 文件（见上）。只记用户主动改动，不把 agent 自己的修改记成用户偏好。

## 三次编辑，修不同的问题

1. **事实与论证**：检查结论对应的证据、版本、比较对象、样本和条件。将推断写为推断，计划写为计划；不要把相关变因果、局部测试变全面兼容、可能改善变已提升。
2. **结构与读者**：每节推进一个有关的问题，一篇文章只走一条主线——阮一峰所谓「单线结构」，由浅入深、层层递进；多线纠缠的复杂问题拆成多篇。产品文章用场景、动作和结果组织；教程按读者真正执行的顺序组织；观点文章补必要反例和适用边界。删重复的铺垫，不删独立信息或作者立场。
3. **句子与声音**：检查主语、指代、修饰关系和衔接；让动作具体，减少重复和翻译腔。长短句服务于意思，段落不按字数阈值硬拆——AI 稿的典型指纹是把句长抹平成均匀中长句，真人写作长短错落，刻意的短句与单句成段要留住。保留已有幽默、犹豫和正常标点。

中文润色优先调用一个可用的 `humanizer-zh`；已有 `humanizer` 也可用，但以本流程的事实和声音要求为边界。不要串联多个去味技能反复磨平同一篇文章。命中词表只是复查线索，“闭环控制”“进行实验”和有真实纠错作用的“不是……而是……”可以完全正常。

翻译腔病根的权威描述是余光中《怎样改进英式中文》与《的的不休》：抽象名词抢占主语、万能动词加抽象名词架空实动词（「进行了研究」）、被动泛滥、「的」的不休。`humanizer-zh` 的「进行＋动词」「层叠的‘的’」「被字句堆叠」「回避‘是／有’」等条目即这份清单的机器可执行版；判断拿不准时按余光中的原则——动词要实、主语要具体、「的」要省。

## 结构设计

文体先定位再动笔。开发手记是叙说结合：以作者经历为主线，技术解释嵌在故事里；说明文求清楚，议论文求立场——混写可以，主线必须只有一条。

**骨架分型**（借鉴 skillhub「科技公众号写作」的 A/B/C 分型）：事实骨架（围绕可证伪的信息组织，评测/科普/复盘用）、论点骨架（围绕一个判断组织，观点文用）、混合骨架（事实铺底、观点收束，开发手记默认）。定错骨架比写错句子难治——写完才发现论点文写成了资料汇编，只能重来。

**文章原型**各带纪律：方法论/教程——每节落到读者当天可执行的动作，坦诚学习成本和失败点；工具实测——案例包装成微型故事，案例本身要有独立观赏价值；多案例横评——逐一展示带点评，禁一次性罗列结论，排序按升番（最弱的在前，最强的压轴）；复盘——按真实时间线走，不预支结论。

**开头做承诺，正文兑现。** 可用的开头式：SCQA（情境→冲突→问题→回答；西瓜文开头即实例）、事实切入（一条具体可溯源的事实直接开篇）、反差切入（与读者直觉相反的真实对比）、细节特写（一个具体场景/数字/动作）。共同的底线：开头素材必须可溯源，不靠夸张省略制造冲击。结尾三式：数据收束（让数字自己形成判断）、对照收束（与开头呼应成环）、开放式收束（留给读者一个问题）——三种都要求干脆，写完就停。

详略是真人指纹。文似看山不喜平：最有意思的点拿最多的笔墨，不重要的敢一笔带过——西瓜文里物理写足三段、成就图鉴一字未提。AI 的均匀详略（每个特性都得到一段同等篇幅）是结构级破绽，比词汇更难伪装。**并列式慎用**：它是 AI 的默认骨架，每节等长等权重读起来像功能清单；非用不可时各节权重必须参差。

**节奏与数据纪律**（借财新风格 skill）：每个数据必须服务一个判断，没有判断支撑的数字删掉；一段不超过 3 个独立数据点；能用「翻了一倍」「不到三分之一」说清的不堆精确数字（精确数字本身是论据核心的除外，比如 18 个顶点、1/120 秒）；关键结论单独成段；过渡句必须同时承接上文和预告下文，空洞过渡词（「值得注意的是」「首先其次」）删掉。注意边界：这些是叙事密度规则，技术文章里数字就是机制本身时不套——讲 Verlet 积分的参数和引用数据的密度是两回事。

大纲先行但活着用。LLM 长文研究共识是 plan-and-write（STORM、WritingPath、Plan-Before-You-Write：先调研提问、再出大纲、后写正文，组织性与覆盖度显著提升）；但大纲是脚手架不是合同——写中发现更好的线索就改大纲（EMNLP 2025 异质递归规划）。采访提问用 STORM 的视角引导法：从读者、同行、批评者不同视角各拟问题，比泛泛一句「还有什么想补充的」挖得深。

结构级问题的处理原则：审校发现骨架级问题（并列罗列、详略均匀、开头承诺未兑现）两处以上，重排段落重做详略，不在词面打补丁——结构病用句子药治不好。

## 表述检查

| 问题 | 编辑动作 |
| --- | --- |
| “赋能效率”“极致体验”没有具体含义 | 从已有材料恢复谁做什么、结果和条件；缺证据时记为待核验，不制造指标 |
| “这个”“它”“相关内容”指代不明 | 写出对象名称；同一对象的术语保持一致，不轮换同义词 |
| 名词长串、层叠“的”、英文句序 | 按中文动作顺序重组，核对修饰关系；保留 API 名称和代码标识符 |
| 标题后重复标题、时代开场、万能总结 | 删除没有新增意思的句子，保留真实背景与结论 |
| 强行三点、对仗、金句与反转 | 检查是否有独立信息；有信息就保留，空泛才调整 |
| 口语化改变精度 | 恢复数字、单位、否定、范围、时态和限定；自然不等于随意 |

### 语义保真的示例

以下均为教学文本，不是作者的经历或产品实测结果。

原稿：这次升级不仅带来极致体验，更全面赋能创作效率。现在可以把同一份 Markdown 分别整理成公众号和网站稿，但图片仍需核对。知乎适配计划下周测试。

改稿：现在可以把同一份 Markdown 分别整理成公众号和网站稿，图片仍需核对。知乎适配计划下周测试。

不应改成“已经支持一键全平台发布”，也不应删除图片限制或把计划写成已完成。

原稿：关闭缓存时，接口仍可能超时。目前只在 macOS 上测过。

这段可以保留。不能为了简短写成“接口稳定，兼容各个平台”。

## 交付

润色默认给成稿；深度改稿另附少量影响论点、结构或证据的改动说明。需要记录时放 `editorial-report.md`，写具体问题与处理结果，不用“AI 率”“活人感 98 分”代替核验。不要求用户在每个阶段确认；只有关键材料缺口影响准确性或用户要求逐步审批时等待。

成稿前过一次小型评审，每条意见必须给原文证据，没有证据不写：

| 维度 | 评审问题 |
| --- | --- |
| 事实保真 | 有没有主张在素材/facts 里找不到依据？限定、否定、版本、归因是否完整？ |
| 读者收益 | 开头给出的承诺，正文兑现了吗？读者为什么点开、为什么读完？ |
| 文风匹配 | 按 voice 文件抽查：禁用句式、词表、标点偏好有没有漏网的？ |
| 结构推进 | 每节是否推进一个有关的问题？有没有只复述结构不提供信息的过渡？ |

评审表不迷信固定维度：WritingBench（阿里+人大+上交，arXiv 2503.05244）实测固定 rubric 与人判断一致性不足 65%，按写作意图动态生成的指标才到 87%。所以上表是默认骨架，按文章类型加权——产品介绍重「事实保真+读者收益」，技术分享加一问「读者照做能否复现」，观点文把「立场攻击」前置成主维度。

成稿后另过一遍对抗性审校。这一遍的立场不是「文章够不够好」，而是「假定它是 AI 写的，攻击者会拿哪几处当证据」。模型对自己输出的错误有明显盲区（Self-Correction Blind Spot 实测漏检率约 64.5%），所以必须换身份、换语境再审——把稿子当成别人投来的稿件，不带成稿时的自我评价（评审方看到生成者判断会被锚定，多样性归零）。四个攻击面：

- **指纹攻击**：假定审稿人要证明此文出自 AI，列出他会引用的证据——默认结构（均匀段落+结尾总结）、并列骨架与均匀详略（每个特性得到同等篇幅，最有意思的点反而没写透）、每段同长、立场缺席、虚胖量化词（无数字的「大幅提升」「明显改善」，prose_lint 可查）、句尾套话。
- **事实攻击**：假定文章藏着一处事实错误，逐条反证每个可证伪主张——回 facts.md/源码找依据，找不到的标出来，宁删不编。
- **读者攻击**：以不耐烦的读者身份扫读——开头三句有没有理由继续？哪段会跳读、哪句会被截图嘲笑？
- **立场攻击**：找无理由的含糊——该下判断的地方是不是在和稀泥？该留白的推断是不是说满了？

攻击面有优先级。RAID 基准（ACL 2024，600 万条样本、11 种对抗攻击）测下来：检测信号里**表面词频最脆弱**——换个说法、改个标点就蒸发，所以指纹词表只当初筛；**结构性破绽**（段落均匀、无立场、段尾总结）和**事实性破绽**（无依据主张）才扛得住换皮，是主攻面。词表还会随模型版本漂移（Kobak 等的 excess-vocabulary 研究证实 AI 高频词逐年更替，且这些词正反向渗入人类写作）——改稿回收时顺手把新抓到的指纹加进 `--dict`，别让词表变成刻舟求剑。

中文指纹有实证词表可用（JCSA 2026，台政大，硕士生摘要 vs ChatGPT 同题摘要）：AI 中文倾向**短句均质**（句长差异小，burstiness 规律在中文同样成立）、词类与标点多样性低，高频出现「提升/提供/建议/此外/进一步/显示」及**「X性」抽象名词**（稳定性/适用性/依赖性——正是余光中批的名词化在 AI 中文里的现代形态）；真人中文的区分特征是「我们」式口语主语、文言虚字「之」、否定句式。prose_lint 已内置「抽象名词化密度」与「句首过渡词堆叠」两项中文专项检查。另外 NLPCC 2025 中文检测基准把「人类文本掺入 <50%」的混写列为最难攻击场景——人机合写（AI 整理+作者立场）天然处于检测低风险区，审校重心因此更该压在事实和立场上，而不是表面字眼。

简繁与地区词是中文特有的破绽面。简繁转换只解决字形不解决词汇（OpenCC 也一样）：台湾说「網路/軟體/影片/資訊」，香港说「網絡/軟件/視頻」——AI 用简体思维写繁体字，或把繁中语料回流成简体残留台湾词，都是一眼破绽。大陆简体稿统一用大陆术语（软件/网络/视频/数据/默认/用户），出现「伺服器/介面/记忆体/随身碟/智慧型」或散落的繁体字即报（prose_lint 已内置地区词与繁体字两项检查）。注意词表带语境边界：「软体」在简中是「软体动物/软体物理」的合法词，「程式化」不算台湾「程式」——机械规则照样会误伤，命中仍由人判断。

对照生成要防裁判偏差。LLM-as-judge 有实证记录在案的三类偏差（MT-Bench，NeurIPS 2023）：冗长偏好（更长≠更好）、位置偏好（先看到的占便宜）、自我偏好（偏袒同模型的产出）。所以对比成稿与对照稿时别标注哪个是 AI 写的、随机摆放顺序、且只让「找证据」不让「打分」——要求给出原文出处本身就在压低这些偏差。

换介质是低成本破盲区的办法：把稿子读出来（macOS 可用 `say -f article.md`）、从后往前倒读一段、或隔一段时间重读——耳朵和逆序都能绕开眼睛的自动化补全，对翻译腔尤其敏感。

对抗审校的边界也要说清：同一模型的再审共享部分盲区，能抬高检出率但不能归零；OpenAI 2023 年下线自家文本分类器（真阳率仅 26%、误报 9%）说明连生成方都做不出可靠的事后检测——所以本流水线把「检测像不像 AI」降级为线索提示，把「事实与风格核验」作为主门禁。检测的真正出路在生成端水印（DeepMind SynthID-Text，Nature 2024），那是平台基建层的事，与写作质量无关。最强的对抗仍是跨模型评审或真人读者——发布后评论区被引用的句子，就是下一轮最好的攻击样本。
