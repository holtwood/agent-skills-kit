# 中文表达与作者声音

用于写初稿、深度改稿和中文审校。默认是个人开发者讲清楚自己的产品、实践与判断，技术准确，语气自然。用户明确风格、文章用途和本人样稿优先于默认。本文件只放可执行规则；规则背后的研究依据见仓库 `docs/WRITING-SKILLS-RESEARCH.md`，写作时无需加载。

## 作者声音

需要长期保持风格时，优先读取文章工作区 `author-voice.md`、项目既有写作配置，其次读取 `~/.config/agent-skills-kit/article-voice.md`。记录读者、语气、术语、样稿路径、喜欢和不喜欢的表达，无需每篇重新问。用户已经明确的偏好可以记录；样稿推断的习惯写为观察，不冒充作者明确要求。仓库不保存个人经历与账号信息。

从本人样稿观察句长、段落推进、观点强度、技术解释深度和收尾方式。借鉴表达方式，不移植样稿中的故事、数字、结论或口头禅。没有样稿就用平实默认，不声称已复刻作者声音。

第一人称只用于作者给出的经历与判断。缺少亲历仍可写好文章，用具体操作、真实例子和解释来支撑，不补写“凌晨三点”“折腾半天”“我当场愣住”等故事。借鉴其他博主时取其方法，不默认变成对方的语气或价值观。

- **风格北极星**：平克《风格感觉》的古典风格——带读者看作者已经看见的东西，呈现事实而非炫耀修辞；简洁但不简单。技术文章最常见的病是「知识的诅咒」：默认读者知道自己知道的事。编辑时问：这段假定读者懂什么？该解释的解释，该给的细节给，该删的背景删。
- **立场是风格资产**：面面俱到的中立比不完美的真实判断更没人味。作者的偏好、取舍、自嘲和有棱角的判断要保留；拿不准时标「推断」，不把犹豫磨成断言，也不把断言磨成和事佬。
- **作者独有素材是抗同质化的唯一可靠来源**：AI 给出的点子单篇看更顺，多篇放在一起却彼此相似，调参数、改提示词都弥合不了。观点、意外、取舍来自作者材料，AI 负责把它们说清楚。缺亲历或立场时按 [文章生产](production.md) 做靶向采访或口述；材料已能回答的不问；用户只要润色或明确不想被打断时不阻塞，在交付说明里列出“缺作者材料、因此写得偏平”的段落。
- **多篇连续产出**时刻意变换开头方式、骨架和收尾，别让一组文章收敛到同一个模子。

两条写法和回收的硬经验：

- 风格规则要具体到可匹配才生效。「自然一点」「口语化」这类抽象指令几乎无效；规则写成下文「看见 X 换成 Y」的替换表，或配 before/after 样例。
- 改稿回收：交付后用户的手改是最高价值的风格信号，把「交付稿 vs 用户改后稿」的差异归纳进 voice 文件。只记用户主动改动，不把 agent 自己的修改记成用户偏好。

## 写前三问

1. **这篇教给读者什么他本来不知道的东西？** 回答不出来先不写。有用的文章是乘积：**正确**（主张放到不出错的最强程度，能用「是」不用「可能是」，推断仍写推断）×**新颖**（最高级是读者心里有但从没说出来的东西）×**重要**（作者自己反复想过、觉得要紧的）；**简洁**省读者时间。任何一项为零，整篇为零。写完全文一个意外都没有，多半是在复述。
2. **So What？** 给每节追问「那又怎样」，直到说到机制或取舍层。「一颗水果由 18 个点组成」停在观察层；「掉帧时物理子步最多补 4 次，宁可慢动作也不让物理崩掉」才是取舍层。答不上来的地方是意义缺口，正是值得深挖的点。
3. **和同题文章差在哪？** 写前搜一圈同题文章，前十条里七条同一个角度就换角度，或找那三条异类。产品文先拆差异化四问：输入、流程、输出、定位哪里不同，答案就是观点锚点。采访时最值钱的问题是「哪一步跟你想的不一样」。

论题是演进的：可以先写最兴奋的分析段，归纳出主张，再回验其他证据。开头是邀请不是剧透，结尾的判断应比开头更准、更厚。引用外部信息时，信源分四级：T1 官方/原始数据优先，T2 研究与数据库可用，T3 自媒体只作线索（核心事实须 T2 以上），T4 匿名传言不用。

## 结构设计

文体先定位再动笔。开发手记叙说结合，以作者经历为主线，技术解释嵌在故事里；说明文求清楚，议论文求立场。混写可以，主线只有一条——阮一峰所谓「单线结构」，由浅入深、层层递进；多线纠缠的问题拆成多篇。

**骨架分型**：事实骨架（围绕可证伪的信息，评测/科普/复盘用）、论点骨架（围绕一个判断，观点文用）、混合骨架（事实铺底、观点收束，开发手记默认）。定错骨架比写错句子难治，动笔前先定。

**文章原型纪律**：

- 方法论/教程：按读者真正执行的顺序组织，每节落到当天可执行的动作，坦诚学习成本和失败点。
- 工具实测：案例写成微型故事，案例本身要有独立观赏价值。
- 多案例横评：逐一展示带点评，不一次性罗列结论；由弱到强排列，最强的压轴。
- 复盘：按真实时间线走，区分当时的判断和事后的判断，不预支结论。
- 观点文：补必要反例和适用边界。

**开头做承诺，正文兑现。** 开头可选：SCQA（情境→冲突→问题→回答）、事实切入（一条可溯源的具体事实）、反差切入（与读者直觉相反的真实对比）、细节特写（一个具体场景、数字或动作）。开头素材必须可溯源，不靠夸张或省略制造冲击。结尾可选：数据收束（让数字自己形成判断）、对照收束（与开头呼应）、开放收束（留一个真问题）、行动收束（读者下一步能做什么）。写完就停，不升华、不喊口号。

**详略是真人指纹。** 文似看山不喜平：最有意思的点拿最多笔墨，不重要的敢一笔带过。每个特性分到同等篇幅是结构级破绽，读起来像功能清单。并列式慎用；非用不可时各节权重必须参差。

**事实表不是大纲。** `facts.md` 保证正文每个字有据可查，不是逐行搬运的清单。抓 1–2 个核心卖点写透，其余次要细节（冷门错误码、琐碎配置开关）舍弃或退为背景。

**节奏与数据**：每个数据服务一个判断，不支撑判断的数字删掉；一段不超过 3 个独立数据点；能用「翻了一倍」「不到三分之一」说清的不堆精确数字；关键结论可单独成段；过渡句同时承接上文、预告下文。边界：技术文章里数字就是机制本身时（参数、阈值、帧间隔）不套这条。

**大纲先行但活着用。** 先调研、再列大纲、后写正文；写中发现更好的线索就改大纲。审校时发现骨架级问题（并列罗列、详略均匀、开头承诺未兑现）两处以上，重排段落、重做详略，不在词面打补丁——结构病用句子药治不好。

## 三次编辑，修不同的问题

1. **事实与论证**：检查结论对应的证据、版本、比较对象、样本和条件。推断写为推断，计划写为计划；不把相关变因果、局部测试变全面兼容、可能改善变已提升。
2. **结构与读者**：每节推进一个有关的问题；删重复铺垫，不删独立信息或作者立场；产品文章用场景、动作和结果组织。
3. **句子与声音**：检查主语、指代、修饰关系和衔接；让动作具体，减少重复和翻译腔。长短句服务于意思，段落不按字数阈值硬拆；把句长抹平成均匀中长句是 AI 稿的典型特征，刻意的短句与单句成段要留住。保留已有幽默、犹豫和正常标点。

翻译腔的判断原则来自余光中《怎样改进英式中文》《的的不休》：动词要实、主语要具体、「的」要省。

## 看见 X，换成 Y

命中只是复查线索，有独立信息、有真实纠错作用的照样保留。「闭环控制」「进行实验」在专业语境完全正常。

| 看见 | 换成 |
| --- | --- |
| 「进行了分析/优化/测试」「对 X 进行 Y」 | 直接用动词：「分析了」「优化了 X」「测了 X」 |
| 「X 性」抽象名词作主语：「系统的稳定性得到提升」 | 让具体对象做动作：「系统崩得少了」，再补条件和数据 |
| 「被」字句堆叠、「得到了……的改善」 | 改主动句，写清谁做了什么 |
| 层叠的「的」：「用户的数据的导出的格式」 | 拆句或换动词：「用户导出数据时用什么格式」 |
| 「通过……，实现了……」 | 「做了 A，于是 B」，动作和结果分开说 |
| 「随着……的发展」「在……的背景下」「如今……」时代开场 | 删掉，从具体场景、事实或问题开始 |
| 「本文将介绍」「接下来让我们一起看看」「下面逐一介绍」 | 删掉，直接开始讲 |
| 「值得注意的是」「需要指出的是」「众所周知」「毋庸置疑」 | 删外壳，直接说那件事 |
| 段末「这说明」「由此可见」「总之」「综上所述」 | 删掉不损失信息就删 |
| 句首「此外/同时/因此/然而」连用 | 砍掉一半，靠内容本身衔接 |
| 「赋能」「极致体验」「全面提升」「打通」等黑话 | 从材料恢复谁做什么、结果和条件；缺证据记为待核验，不造指标 |
| 「大幅」「显著」「明显」却没有数字 | 补数字和条件；没有数据就写实际观察到的现象 |
| 「颠覆」「革命性」「彻底改变」「重新定义」 | 写具体改变了哪一步；改变不大就别用 |
| 「简单、高效、优雅」三连形容词 | 选一个有证据的，写成动作或结果 |
| 「X 不是 Y，而是 Z」金句公式、强行对仗与反转 | 只在纠正真实误解时用；否则直接陈述 Z |
| 「为什么？因为……」「……可不是……那么简单」「做起来比说起来难」 | 删掉虚张声势的铺垫，直接写机制或决策 |
| 「这里有个坑」「有个细节」式铺垫壳 | 直接陈述那个坑 |
| 「这个」「它」「相关内容」指代不明 | 写出对象名称；同一对象术语保持一致，不轮换同义词 |
| 「X 约束、Y 模式、Z 参数」术语排排站；「有 A、B、C 三种」先报名单 | 换成各自在做什么的动作描述；名字带上当场说明 |
| 「未来可期」「让我们拭目以待」「一起加油」 | 删掉，用事实、限制或下一步收尾 |
| 「某种程度上」「可以说」「在一定意义上」层层含糊 | 能下判断就下；拿不准写清不确定在哪 |
| 口语化后丢了数字、单位、否定、范围、时态 | 恢复原精度；自然不等于随意 |

用词统一用大陆简体与大陆技术术语（软件/网络/视频/数据/默认/用户/内存）。出现「伺服器/介面/记忆体/智慧型/程式」或散落的繁体字即改。简繁转换只换字形不换词汇，地区词要逐个替换；「软体动物」「程式化」等合法简中词不算。

## 改写样例

以下均为教学文本，数字和经历不是作者产品事实；实际改稿中的数字与经历必须来自材料。

**翻译腔与名词化**

- 原：通过对缓存策略进行优化，系统的响应速度得到了显著的提升，用户体验也得到了进一步的改善。
- 改：把缓存过期时间从 5 分钟改成 30 分钟后，列表页首屏从 1.2 秒降到 0.4 秒。
- 没有测过耗时：如实写「没测具体耗时，自己用起来不再等转圈」，不编数字。

**时代开场**

- 原：随着 AI 技术的飞速发展，越来越多的开发者开始用大模型辅助编程。在这样的背景下，我开发了一款记账小程序。
- 改：上个月我给记账小程序加了拍小票自动记账。这篇讲它怎么做的，以及哪一步比预想的难。

**功能清单体 → 单线与详略**

- 原：本次更新包含三大亮点：一是支持深色模式，二是新增数据导出，三是优化了启动速度。下面逐一介绍。
- 改：这次更新最花时间的是数据导出，因为……（展开两三段）。深色模式和启动优化是顺手做的，文末一句带过。

**口号式结尾**

- 原：总之，技术没有终点，只有不断探索，才能做出真正打动用户的产品。未来可期！
- 改：导出目前只支持 CSV，Excel 排在下个版本。

**金句与虚张声势**

- 原：它简单、高效、优雅，不是一个工具，而是一种全新的工作方式。为什么？因为它可不是简单的格式转换。
- 改：它只做一件事：把 Markdown 转成公众号能直接粘贴的 HTML，图片自动内联，不用一张张重新上传。

**语义保真**

- 原：这次升级不仅带来极致体验，更全面赋能创作效率。现在可以把同一份 Markdown 分别整理成公众号和网站稿，但图片仍需核对。知乎适配计划下周测试。
- 改：现在可以把同一份 Markdown 分别整理成公众号和网站稿，图片仍需核对。知乎适配计划下周测试。
- 不应改成“已经支持一键全平台发布”，也不应删除图片限制或把计划写成已完成。
- 「关闭缓存时，接口仍可能超时。目前只在 macOS 上测过。」这段原样保留，不能为了简短写成“接口稳定，兼容各个平台”。

## 润色工具

中文润色优先调用一个可用的 `humanizer-zh`；已有 `humanizer` 也可用，但以本流程的事实和声音要求为边界。不要串联多个去味技能反复磨同一篇文章，反复自我修改会放大既有偏差。`scripts/prose_lint.py` 扫上表中可机械匹配的部分，命中只是复查线索；新抓到的指纹用 `--dict` 追加，AI 高频词会随模型换代变化，词表需要持续更新。

## 交付与审校

润色默认给成稿；深度改稿另附少量影响论点、结构或证据的改动说明。需要记录时放 `editorial-report.md`，写具体问题与处理结果，不用“AI 率”“活人感 98 分”代替核验。不要求用户在每个阶段确认；只有关键材料缺口影响准确性或用户要求逐步审批时等待。

成稿前过一次小型评审，每条意见必须给原文证据，没有证据不写：

| 维度 | 评审问题 |
| --- | --- |
| 事实保真 | 有没有主张在素材/facts 里找不到依据？限定、否定、版本、归因是否完整？ |
| 读者收益 | 开头给出的承诺，正文兑现了吗？读者为什么点开、为什么读完？ |
| 文风匹配 | 按 voice 文件抽查：禁用句式、词表、标点偏好有没有漏网的？ |
| 结构推进 | 每节是否推进一个有关的问题？详略是否参差？有没有只复述结构的过渡？ |

固定维度和人的判断一致性有限，按文章类型加权：产品介绍重「事实保真 + 读者收益」；技术分享加一问「读者照做能否复现」；观点文把「立场」前置为主维度。

成稿后另过一遍对抗性审校。模型对自己刚写的东西有明显盲区，所以要换身份：把稿子当成别人投来的稿件，不带成稿时的自我评价。五个攻击面：

- **结构攻击**：均匀段落、并列骨架与均匀详略、每段同长、段尾总结、默认的「背景→三点→总结」结构。
- **事实攻击**：假定文章藏着一处事实错误，逐条反证每个可证伪主张，回 facts.md/源码找依据，找不到的标出来，宁删不编。
- **读者攻击**：以不耐烦的读者身份扫读——开头三句有没有理由继续？哪段会跳读、哪句会被截图嘲笑？
- **立场攻击**：该下判断的地方是不是在和稀泥？该留白的推断是不是说满了？
- **增量攻击**：逐段问「这段给了读者什么他不知道的东西」。答不上来的段删掉，或追问 So What 补出取舍层再留。来历与履历不自动等于信息：「参考了某 demo」「我把 X 直译过来」类交代，除非来历本身是设计判断的依据，否则删。

攻击面有优先级：结构和事实破绽换个说法也藏不住，是主攻面；表面词频一改就变，只作初筛。“像不像 AI”只是线索，事实与风格核验才是门禁。

对比成稿与对照稿时，不标注哪个是 AI 写的，随机摆放顺序，只让找证据不让打分，压低冗长、位置和自我偏好。换介质能绕开眼睛的自动补全：把稿子读出来（macOS 可用 `say -f article.md`）、从后往前倒读一段、或隔一段时间重读，对翻译腔尤其敏感。条件允许时请另一个模型或真人读者审一遍；发布后评论区被引用的句子，是下一轮最好的攻击样本。
