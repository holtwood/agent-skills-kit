# 母稿与平台适配

只有用户要求的目标才生成版本。母稿承载事实和完整论点；平台稿可以调整详略和结构，但事实、作者立场、版本与重要限制保持一致。以下是编辑策略，不是平台算法结论或永久的发布规格。

| 目标 | 编辑重点 | 本地交付 | 实际验证 |
| --- | --- | --- | --- |
| 微信公众号 | 具体场景开篇，移动端可读，图注和必要操作入口 | `article-wechat.md`、封面、双 HTML | HTML 终检、390px 预览、实际编辑器图片转存 |
| Astro 网站 | 长期可检索的标题、完整步骤/引用/版本，保留代码 | `article-astro-body.md`、按网站 schema 生成的 `article-astro.md`、资源清单 | 内容 schema、站内链接、代码高亮、站点构建 |
| 知乎 | 开篇回答明确问题，依据、比较与适用边界更充分 | `article-zhihu.md`、标题/摘要、配图和引用 | 指定文章或回答入口，编辑器代码/表格/图片回读 |
| 今日头条 | 减少预设知识，解释必要术语，清楚交代场景和实用信息 | `article-toutiao.md`、标题/摘要、配图 | 当前标题限制、标题层级、特殊字符和图片保存回读 |

不要宣称知乎必然偏好长文、头条必须煽情或某标题有固定 CTR。标题承诺必须由正文兑现。默认不加入“关注公众号”“扫码体验小程序”等跨平台不适用的 CTA；依据实际账号、链接与编辑器支持选择。

## 改写顺序

先定各平台读者要回答的问题，再调整标题、开篇、解释深度和结尾。没有改写必要的段落直接复用。重要限制跟着相关主张走，不能只留在母稿。小程序码、二维码和宣传截图不替代其他平台可读的文字说明。

每个平台单独整理链接和素材，保留图注、替代文字、来源与文件路径。代码尽量保留可复制文本，长表格按目标可读性拆为段落或列表；图解可以另附 PNG。网站用 SVG 时仍给公众号/知乎/头条准备位图，不把交互 HTML 或 MDX 组件直接塞进它们的正文。

修正事实时先改母稿与简报，再核对所有涉及该事实的版本。公开发表后需要修改线上内容时遵循用户本次授权，记录真实更新时间与链接。

## Astro 接入

先读取网站 `package.json`、`astro.config.*`、`src/content.config.*` 或旧版 `src/content/config.*`、至少一篇现有文章与文章布局。根据实际 loader、collection、schema 与日期字段确定目录和 frontmatter，不能假定 `src/content/blog`、`pubDate`、`coverImage` 是通用约定。依据当前项目版本工作，不因官网版本更新而顺带升级网站。

- schema 中字段名、类型、必填项和图片处理优先；沿用站点日期、标签、slug 与作者约定。
- 默认用 Markdown；只有现有网站支持并确需组件才用 MDX。可选脚本生成普通 Markdown frontmatter，不处理 MDX import。
- 图片路径相对最终文章位置校验。复制正文和 `img/` 时保持关系；放 `public/` 则按真实 URL 规则修改，需 `image()` 验证的字段按现有写法处理。
- 去掉公众号样式、二维码 CTA、章节装饰。页面已经显示标题时，正文不重复 H1。
- description/摘要基于正文，不添加关键词堆砌或无法兑现的承诺。canonical、首发时间、结构化数据仅在站点支持且地址/时间真实时填写；不默认替第三方平台设置 canonical。
- 写入网站仓库并验证只在该仓库属于本次任务范围时执行。按现有脚本运行内容检查和 build；生成 frontmatter 文件本身不等于 Astro 构建通过。

用户只说明 Astro、尚未给出网站路径时，交付通用 Markdown、元数据候选与资源清单，明确待映射 schema，不阻塞其余平台。

依据：[Astro 内容集合](https://docs.astro.build/en/guides/content-collections/)、[Astro Markdown](https://docs.astro.build/en/guides/markdown-content/)。具体字段来自目标仓库。

## 平台规则与发布

平台标题长度、外链、格式、首发/原创选项、内容标识和 API 权限会变化；实际保存或发布前以当前官方说明、账号能力和编辑器反馈核对，不在本 skill 中固化字符数或模拟流量评分。跨平台已有版本时按真实情况处理首发/原创字段。

md2wechat 的跨平台能力是“CLI 准备 + 浏览器保存未发布草稿”；知乎/头条不是一次转换就公开发布。执行前读取当前 CLI 嵌入的 `references/sync/workflow.md` 与单个平台说明。工具和格式均可用才写入；本地稿件交付不依赖登录。每个平台的图片分别上传，不跨平台复用私有图片地址。

知乎区分文章与回答，不能拿同一入口处理。头条等编辑器可能归一标题层级或移除字符，先在平台副本做用户已授权的适配，核对保存后正文；转换损失不能用字数相近或保存提示掩盖。

新增 CSDN、掘金、腾讯云、博客平台时沿用上述决策：读者/目标、格式、素材、当前规则和实际发布能力。先交付平台稿，再按授权进入账号，不声称不存在的“一键全平台发布”。
