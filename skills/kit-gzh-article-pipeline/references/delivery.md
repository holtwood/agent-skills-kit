# 排版、依赖与交付

## 依赖按需加载

| 能力 | 何时需要 | 缺失时 |
| --- | --- | --- |
| humanizer-zh 或已有 humanizer | 文风编辑 | 按写作规则直接编辑底稿 |
| content-headline-hacker | 多角度标题 | 直接生成有事实依据的候选，不报未经实测 CTR |
| topic-pool | 选题/排期 | 用户指定产品则跳过，否则遵循工作区现有格式 |
| wechatide-skill 或对应截图能力 | 新采集运行画面 | 复用作者真实截图，缺图不虚构 |
| gzh-design 组件与校验器 | 默认公众号 HTML 交付 | 可选择可用的其他引擎并执行其检查；否则交付已有材料 |

写作/标题/选题依赖是可选增强。`check_article.py` 适用于默认 gzh-design 双产物，依赖其校验器，不是所有 HTML 引擎的统一门禁。其他引擎读取 [技能协作](integrations.md)，遵循其检查流程并说明验证差异，不能报告 gzh-design 终检通过。

## 封面与正文

复制 `assets/cover.html` 到文章目录，替换全部占位符和截图。执行 `render_cover.sh`；DOM 校验头图 1800×766、方图 1000×1000 和 top≈774，图片应加载成功。输出头图 1800×766 与次图 500×500。

默认正文使用所选 gzh-design 组件；输出存档版 `article-gzh.html`（本地图片路径）及粘贴版 `article-gzh-embedded.html`（base64 图片）。使用 `python3 <SKILL_ROOT>/scripts/embed_images.py <文章目录>` 一键生成并清洗合规，该内联文件是全选复制直达微信公众号后台编辑器的**唯一终极交付物料**（直接粘贴即可被微信自动转存为平台 CDN 图片，杜绝碎图）。两份正文、图片数量与顺序必须完全一致。

排版装饰层（封面卡、眉标、目录看点、图注、署名区、CTA）可填模板固定词表（编号、日期、互动客套话、署名占位）、母稿摘句和不带事实主张的修辞短句；**禁止引入母稿没有依据的可证伪主张**——功能、数据、机制、文章性质定性词都属此类。装饰层文案与正文一样纳入事实核对范围，发现新造主张视同漏检，删改或回落为中性标签。

`article.md` 等母稿是唯一手工编辑面；`article-gzh.html`、embedded 版等排版产物是派生物，改稿一律改母稿后重新生成，不直接手改产物——手改会在母稿与产物之间造出第二个事实源，且下次重新排版时被静默覆盖。

排版机械层（中英文与数字间空格、标点全半角、重复标点）交给工具检查，不写进文字规则：在 `articles/` 工作区根放 `.zhlintrc` 固化本项目约定（如全角括号、`「」`直引），跑 `npx zhlint <article.md>`；基线标准是《中文文案排版指北》，句法底线参考阮一峰《中文技术文档的写作规范》。

文风指纹交给 `scripts/prose_lint.py`：扫铺垫句式、段末信号词、翻译腔、互联网黑话、AI 元话语、时代开场、元叙述、夸大词、广告法风险词、虚胖量化、抽象名词化、过渡词堆叠、地区词/简繁混用、句首复读与句长方差，输出复查线索。各平台稿同样可以跑。命中不判失败（合法语境可以有这些词），`--strict` 才卡门禁；自定义词表用 `--dict` 追加。

## 完成条件

gzh-design 终检实际解码图片、比较文本/图片摘要、拒绝占位符与禁用标签、调用外部兼容校验。外部校验器缺失、警告或超时即失败。普通标点默认允许；历史编辑偏好用 `--text-policy legacy`，限制破折号、全角冒号与弯双引号。

其他引擎至少对照其输入稿核验正文、层级、代码、表格、引用和全部图片，检查残留占位与不兼容内容；渲染器自身报告不替代这些比较。选择 md2wechat 时读取当前 `inspect` readiness 与诊断；纯转换、预览、上传和草稿各自按当前工具要求执行。不要为已有的有效排版结果补造一个“兼容性通过”状态。

按可用浏览器能力检查桌面与 390px 手机渲染，核对图片可读、图注匹配、封面裁切和 CTA。事实与语言另行通读，机器报告不能替代事实核验。完整文章所有产物完成才称成稿；只完成底稿时说明实际交付范围。

发布前做一次事前验尸（pre-mortem）：假设明天有读者截图说「这段一看就是 AI 写的」，会是哪三处？逐处确认站得住再发。另过一遍合规词：广告法高危表达（「最」「第一」「100%」「稳赚」「包过」「根治」类绝对化与收益承诺词）不在事实底稿与正文出现——这类词不只是文风问题，金融、健康、教育向内容会触发强审核。

## 发布与归档

按当前账号与工具确定发布方式，不从个人订阅号的历史经验推断所有账号 API 权限。用户只要求成稿时交付文件。用户要求发布但自动工具不可用时交付可粘贴 HTML 和操作所需素材，明确尚未发布。

《人工智能生成合成内容标识办法》自 2025-09-01 施行，用户发布生成合成内容应主动声明并使用平台标识功能。公众号、知乎、头条、搜狐等编辑器各有 AI 创作声明选项；内容主要由 AI 生成的文章，交付说明里逐平台提醒用户在发布时勾选，是否勾选由用户按其内容实际决定。

粘贴内嵌版后检查编辑器实际图片转存与手机预览；失败按实际环境处理。真机/手机预览额外过一遍视觉清单：首屏是不是一个完整的信息单元（刊头+开头钩子放得下）；大章节分隔是否一眼可见；横线、竖线、色块、外框是否过多（装饰密度宁少勿多）；标题折行有没有难看的断点；正文行距字号在长读下是否舒适。真实发布后才回填链接与台账，后续数据采集不阻塞成稿任务。
