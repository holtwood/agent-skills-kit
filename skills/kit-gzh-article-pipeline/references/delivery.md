# 排版、依赖与交付

## 依赖按需加载

| 能力 | 何时需要 | 缺失时 |
| --- | --- | --- |
| humanizer | 文风编辑 | 直接编辑底稿，明确未执行其专用检查 |
| content-headline-hacker | 多角度标题 | 直接生成有事实依据的候选，不报未经实测 CTR |
| topic-pool | 选题/排期 | 用户指定产品则跳过，否则遵循工作区现有格式 |
| wechatide-skill 或对应截图能力 | 新采集运行画面 | 复用作者真实截图，缺图不虚构 |
| gzh-design 组件与校验器 | 公众号 HTML 交付 | 保留底稿、素材与封面，HTML 阶段明确未完成 |

写作/标题/选题依赖是可选增强；当前自带 HTML 终检依赖 gzh-design 校验器。这是本流程的实现契约，不代表其他已验证公众号工具必须使用同一引擎。用户选了其他排版引擎时遵循其检查流程并说明验证差异。

## 封面与正文

复制 `assets/cover.html` 到文章目录，替换全部占位符和截图。执行 `render_cover.sh`；DOM 校验头图 1800×766、方图 1000×1000 和 top≈774，图片应加载成功。输出头图 1800×766 与次图 500×500。

正文使用所选 gzh-design 组件；输出存档版 `article-gzh.html`（本地图片路径）及粘贴版 `article-gzh-embedded.html`（base64 图片）。两份正文、图片数量与顺序一致。

## 完成条件

终检实际解码图片、比较文本/图片摘要、拒绝占位符与禁用标签、调用外部兼容校验。外部校验器缺失、警告或超时即失败。普通标点默认允许；历史编辑偏好用 `--text-policy legacy`，限制破折号、全角冒号与弯双引号。

按可用浏览器能力检查桌面与 390px 手机渲染，核对图片可读、图注匹配、封面裁切和 CTA。事实与语言另行通读，机器报告不能替代事实核验。完整文章所有产物完成才称成稿；只完成底稿时说明实际交付范围。

## 发布与归档

按当前账号与工具确定发布方式，不从个人订阅号的历史经验推断所有账号 API 权限。用户只要求成稿时交付文件。用户要求发布但自动工具不可用时交付可粘贴 HTML 和操作所需素材，明确尚未发布。

粘贴内嵌版后检查编辑器实际图片转存与手机预览；失败按实际环境处理。真实发布后才回填链接与台账，后续数据采集不阻塞成稿任务。
