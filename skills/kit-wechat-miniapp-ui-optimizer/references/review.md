# 界面审查与验证

按任务涉及的区域选择检查点，不要求每次重做全项目审计。

- 信息层级：首屏职责、主要操作、留白、对齐、换行与长文案。
- 视觉系统：已有颜色、字号、间距、圆角、阴影 token；状态信息不只靠颜色。
- 状态：加载、空、错误、提交中、禁用、成功与网络失败；按修改区域选择实际场景。
- 交互：点击范围、按下反馈、滚动、输入、弹层与返回上下文。
- 平台：导航/tabBar、安全区、暗色主题、窄屏与字体放大。
- 资源：图片大小、压缩、图标来源、首包与重渲染成本。

Figma 仅在有目标节点和可用连接时读取；将设计值映射到现有 token/组件，不照搬 Web 代码。截图来源、模式和状态应可追溯。若使用微信开发者工具能力，遵循当前安装技能的接口，不把过往机器的 clientName 或接口故障硬编码到流程。

报告区分静态线索、确认问题和运行验证结论。每个确认问题给出位置/画面、影响与处理建议；修改完成附实际检查结果和未验证项。
