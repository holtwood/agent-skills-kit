# Kit WeChat Miniapp UI Optimizer

面向微信原生小程序和混合小程序的 UI 诊断与实现辅助 skill。默认只读：先识别项目形态、设计约束和现有证据，再输出问题清单；只有用户明确授权后才改代码或文件。以 Canvas 为主的微信小游戏使用 `kit-wechat-minigame-ui-optimizer`。

## 何时使用

- 审查微信原生小程序的 WXML/WXSS、页面布局、组件状态和主题。
- 审查同时存在 `src/` 与 `miniprogram/` 的混合项目，区分 Web 端和微信端边界。
- 根据 Figma 节点、设计规范或亮/暗色模拟器截图实现或对比界面。
- 在准备 UI 修改前，快速找出 token、公共样式、页面数量、候选硬编码颜色和已有检查命令。

## 何时不要用

- 只需要生成或编辑一张插画、图标、贴图或其他位图时，使用图像生成/图像编辑能力。
- 只需要截取桌面、网页或开发者工具窗口时，使用 `kit-capture`。
- 只需要给已有截图套设备外框或制作商店宣传图时，使用 `kit-shotframe`。
- 需要改业务规则、数据模型、接口权限或云函数逻辑时，不把 UI skill 当成授权；先确认任务范围。
- 没有 Figma 链接、节点或截图时，不声称已经完成设计稿对比。

## 工作流

1. 读取目标仓库的 `AGENTS.md`、`CLAUDE.md`、README、视觉/交互规格和当前待办；保留用户已有改动。
2. 识别项目形态：原生小程序、混合项目或其他框架；若发现 `game.json`/`game.js` 等 Canvas 游戏入口，切换到 `kit-wechat-minigame-ui-optimizer`。
3. 定位 token、全局样式、公共组件、页面入口、图片资源，以及现有 lint、typecheck、test、对比度和 token 审计命令。
4. 运行本 skill 的只读诊断脚本，再结合源码检查信息层级、布局密度、可读性、状态完整性、点击反馈、平台安全区、资源和性能风险。
5. 有 Figma 时，先获取目标节点的设计上下文，再获取同一节点截图；把设计值映射到项目已有 token 和组件，不直接照搬 Web/React 示例代码。Figma 连接需要用户在当前 Codex 环境中完成登录授权。
6. 用户授权修改后，只做最小范围实现；运行项目已有检查，并以微信开发者工具模拟器或真机截图验证亮色、暗色和关键状态。无法取得真实渲染证据时明确标记为未验证。
7. 交付时列出问题证据、改动文件、自动检查、截图/环境阻塞和未处理范围；不自动提交或推送项目仓库。

## 命令契约

脚本只读扫描目标项目，不安装依赖、不修改目标项目。默认输出中文人类可读报告：

```bash
python3 <skill目录>/scripts/diagnose.py <项目目录>
```

参数：

| 参数 | 作用 |
| --- | --- |
| `project-root` | 必填，微信原生小程序或混合小程序项目根目录 |
| `--json` | 输出稳定的 JSON，便于后续汇总多个项目 |
| `--out <文件>` | 将报告写到指定文件；不传时只输出到终端 |
| `-h, --help` | 查看帮助 |

PowerShell 下可以直接使用：

```powershell
python .\scripts\diagnose.py D:\github\holtwood\classmate-timetable
```

```powershell
python .\scripts\diagnose.py D:\github\holtwood\recipegrid --json --out .\reports\recipegrid-ui.json
```

## 审查重点

- 任务与层级：首屏是否立即说明页面职责，主操作是否突出。
- 布局与可读性：留白、对齐、换行、长文案、窄屏和大字号是否稳定。
- 视觉系统：是否复用颜色、字号、间距、圆角、阴影和动效 token；状态是否不只靠颜色。
- 状态完整性：加载、空、错误、提交中、禁用、成功和网络失败是否可理解。
- 交互反馈：可点击区域、按下态、滚动、弹层、输入和返回后的上下文是否可靠。
- 平台表现：导航栏、tabBar、系统字体、暗色模式、安全区和低端机渲染。
- 资产与性能：图片尺寸、压缩、图标来源、首屏包体和页面渲染成本。

## 实现说明

- `scripts/diagnose.py` 仅依赖 Python 标准库，支持 Windows、macOS、Linux 和 WSL。
- 扫描会跳过 `.git`、`node_modules`、构建产物、覆盖率和测试目录，避免把依赖或测试夹具误计入生产 UI。
- 检查的是候选硬编码颜色和 token 线索，不替代 WCAG 对比度计算、微信开发者工具预览或真机验收。
- Figma 仅在有链接/节点并且 Figma MCP 已连接时参与；纯代码诊断不需要 Figma 登录。
- 不引入 Taro、uni-app、重型 UI 框架或运行时依赖；也不替用户决定是否改变产品范围。

## 常见问题

- **为什么报告里有硬编码颜色？** 这是静态候选项，图标 SVG、合法品牌色或平台样式可能需要人工确认；优先查看项目的 token 权威文件。
- **为什么没有截图结论？** 静态脚本不能证明微信实际渲染结果；请提供开发者工具/真机截图，或在可用环境中重新打开项目验证。
- **Figma 一定要登录吗？** 纯代码扫描不需要。要读取私有 Figma 文件、节点上下文或设计稿截图，需要在当前 Codex 环境完成 Figma MCP 授权。
- **脚本会改项目吗？** 不会，除非你主动使用 `--out` 指定报告文件；建议把报告写到项目外或明确的报告目录。
