# Skill 编写与维护规范

技能入口只保留会改变 Agent 决策的任务规则。现有名称使用 `kit-` 前缀，保持目录名与 frontmatter `name` 一致。

## 结构

```text
skills/kit-example/
├── SKILL.md                 # 能力、触发、关键流程、完成条件
├── scripts/                 # 需要重复或确定性执行的实现（可选）
├── references/              # 模式/平台/参数细节，按需读取（可选）
└── assets/                  # 输出中需要的模板或素材（可选）
```

不为统一外观创建空目录或占位文件。技能脚本必须在只复制本技能目录后仍可运行，不引用仓库 tools 或兄弟目录。编排型技能明确可选增强、必需外部能力与缺失时的实际交付。

## 精简入口

```yaml
---
name: kit-example
description: 描述具体能力和触发任务，只在需要时补最容易混淆的边界。
---
```

本仓库 frontmatter 采用 `name`、`description` 两个字符串；复杂标点用双引号。描述避免穷举关键词、用户案例和全部参数。自动发现保持可用，不因某步骤需要授权就把整个技能设为仅显式调用。

正文写清目标、必要步骤、关键约束、调用方法和完成证据，不强制“何时使用/不要用/FAQ”等固定八段模板。简短技能不需要参考路由；复杂参数、平台矩阵和独立阶段移到 `references/` 并用相对 Markdown 链接说明何时读取。入口原则上控制在 80 行以内，但不以删掉真实契约换取行数。

## 用户意图与证据

用户要求审查就审查，要求优化就在已授权范围内修改。不要把历史确认门、某次工具故障、个人账号权限或标点偏好扩展为所有任务的硬规则。实际外部写入遵循本次任务授权，在需要批准时先做好可审查产物。

技能流程、用户工作区数据与本机事实分层。只声称实际完成的检查；静态线索不能替代运行画面、性能测量或事实核实。失败不交付旧文件冒充新结果。

## 脚本契约

- Bash 兼容系统 Bash 3.2；严格模式或降级分支需显式处理失败。
- Python 3.9+ 标准库优先，`main()` 入口；所需外部工具/包在对应命令附近说明。
- `--help` 在无登录、无浏览器、无网络时可用，不产生安装/写入副作用。
- 参数错误先于下载或外部写入；默认退出码 0 成功、1 运行失败、2 参数错误，特殊退出码要文档化。
- JSON stdout 保持可解析，日志走 stderr；路径使用参数与技能根目录，不依赖调用者 cwd。
- 拉取与截图先写临时文件，验证后替换目标；失败保留上一份有效文件，临时文件结束时清理。
- 已有 workflow 默认保留；明确覆盖时使用 `--force`。Pages 写入提供只读 `--dry-run`。

## 验证

```bash
python3 tools/validate_skills.py
python3 tools/check.py
python3 tools/check.py --render
```

元数据检查涵盖名称、非空描述、相对链接、参考可达性、命令脚本与中英文索引。离线回归验证实际行为：保留文件、安装链接、分页/公开数据范围、报告机器读取与无远端写入的预演。测试不依赖作者机器的文章路径；真实文章对接通过 `GZH_ARTICLE_SMOKE_DIR` 显式选择。

改动渲染器或文章终检时运行其已有回归；需要浏览器证据时追加 `--render`。新增技能更新两个 README 索引，不额外复制一份 SKILL 正文用于评审。
